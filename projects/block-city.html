Context

What is Block City?

A free educational city-builder for children aged 8–9 where all progression is gated behind solving three-step unit conversion maths puzzles. The central hypothesis: interactive reward systems motivate mathematical engagement more effectively than rote practice.

"Careful design ensured players could never soft-lock their progression — and emergent behaviour revealed an unplanned creative layer we leaned into."
How it works

Core Loop

Solve puzzle→Earn coins→Build→City grows→Next puzzle

Players start with an empty village. Each building corresponds to a specific maths challenge. Solving it earns coins to physically construct that building. An anti-softlock constraint was hard-coded into every progression branch.

My responsibilities

Design & Production

Design
  • Designed all unit conversion puzzles, progressively increasing in difficulty for ages 8–9.
  • Built balance spreadsheets: difficulty mapping, coin reward formulas, building unlock logic.
  • Generated JSON tables for direct import into Construct.
  • Implemented buildings, triggers, UI, and SFX directly in Construct.
Production
  • Led full production cycle: milestones, sprint structure, timely delivery.
  • Maintained communication between designer, programmer, and artist.
  • Created GDD, production schedule, and task tracking docs.
Key decisions

Challenges

Balancing educational rigour with game feel. The puzzles needed to be genuinely challenging without feeling punishing. Significant iteration on feedback: how the game communicates wrong answers and scaffolds retry attempts.

Using JSON tables for puzzle data meant content changes didn't require touching code — but it forced me to think in data structures rather than just design documents. That shift in thinking influenced every project since.
